# Архитектура DRUGDIS

Схемы оркестрации и примеры работы собраны в [README](../README.md). Здесь описаны контракты: где модель принимает решения, что она не может сделать, как деградирует система и как расширять.

## Паттерн

Иерархическая система с обратной связью: **планировщик (локальная Qwen)** → **маршрутизатор инструментов** → **агенты-исполнители** → **критик** → **review**. Критик может вернуть систему на один дополнительный шаг.

Ключевое правило:

> **LLM выбирает варианты, инструменты производят числа.**
> Модель никогда не возвращает значение, только индекс в списке, который собрали инструменты, плюс обоснование. Обоснование попадает в Evidence как `hypothesis` с указанием модели.

Это даёт управление на естественном языке без риска выдуманных результатов.

## Где именно работает LLM

| Решение | Из чего выбирает | Агент | Что будет без LLM |
| --- | --- | --- | --- |
| Сценарии и сущности запроса | текст пользователя | `planner` | ключевые слова и транслитерация с проверкой по PubChem |
| Набор инструментов | каталог, обязательные шаги неснимаемы | `tool_router` | фиксированный маршрут сценария |
| Мишень | кандидаты из BindingDB с числом кристаллических комплексов в PDB | `target_agent` | человек, затем больше комплексов, затем сильнее связывание |
| Структура PDB | кандидаты поиска RCSB: разрешение, цепи, ионы, наличие лиганда | `structure_agent` | комплекс с этим лигандом, затем лучшее разрешение |
| Поза для подробного осмотра | кандидаты, уже посчитанные кодом | `pose_comparison_agent` | первый кандидат по детерминированным правилам |
| Достаточность ответа | собранные Evidence | `critic` | шаг пропускается |
| Пересказ | собранные Evidence | `narrate_with_llm` | перечисление фактов программой |

Любой пункт деградирует независимо: без Ollama система работает целиком, честно помечая, что выбор сделан эвристикой.

## Что модель не может сделать

| Попытка | Защита |
| --- | --- |
| Вернуть индекс вне списка | `decide()` отбрасывает ответ, агент работает эвристикой |
| Назвать мишень, которой нет в запросе | подсказка принимается, только если слова есть в тексте запроса (`_honour_named_target`) |
| Назвать UniProt-код или PDB ID | идентификаторы резолвят UniProt и RCSB; код в тексте без Evidence ловит `review_agent` |
| Обосновать выбор тем, чего нет в данных | обоснование сверяется с карточкой варианта и заменяется фактическим |
| Подставить заглушку из примера промпта | `_is_real_ligand_name`, `_usable_ligand` в `agents/planner.py` |
| Подсунуть несуществующий путь к файлу | путь принимается только если файл существует |
| Убрать обязательный шаг маршрута | `required_tools()` добавляет его обратно |
| Написать число, которого нет в Evidence, или приписать число не той величине | `review_agent`: правила привязки `_TERM_TO_METHODS` |

## Роли агентов

| Агент | Назначение | LLM |
| --- | --- | :---: |
| `planner` | сценарии и сущности | да |
| `tool_router` | набор инструментов под сценарий | да |
| `chemistry_agent` | структура молекулы, RDKit-дескрипторы и фильтры | нет |
| `data_agent` | BindingDB, ChEMBL, PubChem, RAG (`collect_target_data`, `report_activities`, `run_rag`) | нет |
| `target_agent` | выбор мишени, accession UniProt | индекс |
| `structure_agent` | лестница поиска структур A–D, цепи, кофакторы | индекс |
| `docking_agent` | P2Rank, подготовка рецептора, Vina, контроль редокинга | нет |

| `analysis_agent` | сравнение карманов, тепловая карта | нет |

| `validation_agent` | семь геометрических проверок, вердикт | нет |
| `writer` | `report.md` из Evidence | нет |

| `review_agent` | контракт Evidence и текста | нет |

## Evidence и статусы

Каждое значение — `Evidence(kind, value, unit, source, method, context)`.

| `kind` | Значение |
| --- | --- |
| `database` | из внешней базы, с `fetched_at` и пометкой «живое/кеш» |
| `calculation` | посчитано в этом запуске: Vina, RMSD, дескрипторы, расстояния |
| `prediction` | выход обученной модели: балл и ранг кармана P2Rank |
| `hypothesis` | рассуждение языковой модели |

Статус ответа: `success` (всё выполнено), `partial` (часть шагов не дала результата), `needs_clarification` (запрос неоднозначен), `no_data` (источники ничего не вернули), `error` (расчёт или проверка не состоялись).

## Деградации: что происходит, когда что-то недоступно

| Что недоступно | Поведение | Видно пользователю |
| --- | --- | --- |
| Ollama / Qwen | эвристики вместо решений модели; в контейнере остановка с ошибкой | `planner: keyword`, ограничение в ответе |
| ChEMBL (HTTP 500) | активности из него не входят в ответ | ограничение «источник не ответил, это не значит, что измерений нет» |
| UniProt не подтвердил имя | мишень выводится без accession | ограничение, поиск структуры уровнем D |
| Нет кристалла с этим лигандом | структура уровня B или C | уровень поиска входит в ответ как факт |
| pdb2pqr / Meeko не отработали | откат на упрощённую подготовку рецептора | явное предупреждение о занижении качества |
| P2Rank нашёл меньше трёх карманов | докинг только в найденных | ограничение «список не дополнялся» |
| Нет Vina или P2Rank | расчёт не выполняется | ошибка, а не подставленный результат |
| Нет RDKit | ошибка | дескрипторы не оцениваются приблизительно |

## Потоки данных

1. NL-запрос → `ResearchRequest` → `WorkflowState`.
2. Агенты пишут в `state.evidence` (с дедупликацией), `state.artifacts`, `state.limitations`, `state.observations`.
3. Исполнитель достраивает недостающие входы шагами-производителями (`OBSERVATION_PRODUCERS`).
4. Критик при необходимости добавляет один шаг.
5. Пересказ → `review_agent` → при провале замена на перечисление фактов → `ResearchResult` + `agent_trace`.

Состояние одного запроса независимо от остальных; лимит — 40 шагов, повтор упавшего шага — один раз.

## Как добавить сценарий

1. Описать `ScenarioSpec` в `orchestration/scenarios.py`: идентификатор, обязательные входы, демо-запрос, ожидаемый ответ.
2. Если сценарий производит вход для других, добавить его в `OBSERVATION_PRODUCERS`.
3. Реализовать агента: он читает и пишет `WorkflowState`, числа только из инструментов.
4. Зарегистрировать обработчик в `orchestration/handlers.py` и инструменты в `orchestration/tool_router.py`.
5. Если агент выдаёт новые `method` с числами, добавить правило привязки в `_TERM_TO_METHODS` (`agents/review_agent.py`) и порядок в `_ANSWER_FIRST` (`orchestration/workflow.py`).
6. `python cli.py demo` перегенерирует [docs/scenarios.md](scenarios.md) из реального прогона.
